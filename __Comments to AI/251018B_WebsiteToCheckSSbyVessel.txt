There are **three common reasons** why these subfolders are not visible to the browser on GitHub Pages:

---

### **1. GitHub Pages Ignores Folders Starting with an Underscore `_` by Default**

This is the most likely culprit. GitHub Pages uses **Jekyll** by default to build static sites. By design, **Jekyll completely ignores and ignores rendering any folder starting with an underscore `_**` (such as `_ExpData` or `_SurveyStatus`).

#### **The Fix:**

You need to add an empty file named `.nojekyll` to the **root** of your repository (`meitatsu2/_SurveyStatus`). This tells GitHub Pages to bypass Jekyll processing and serve all files and folders as static content, including those starting with `_`.

1. In your local repository `_SurveyStatus` (or directly on GitHub):
2. Create a new empty file named **`.nojekyll`** (with a leading dot, no extension).
3. Stage, commit, and push it to your `main` branch:
```bash
git add .nojekyll
git commit -m "Add .nojekyll to bypass Jekyll folder restrictions"
git push origin main

```



---

### **2. Folder or File Case Sensitivity Mismatch**

Linux web servers (which host GitHub Pages) are **strictly case-sensitive**.

Verify that:

* The folder in your repository is spelled exactly `_ExpData` (matching the uppercase `E` and `D`).
* The files inside are named exactly `vessel_list.json` and `pic.json` (all lowercase).

If the folder in your GitHub repository is named `_expdata` or `_EXPDATA`, the server will return a `404 Not Found` when JavaScript requests `_ExpData`.

---

### **3. The `_ExpData` Folder Was Not Pushed to the `main` Branch**

Ensure that the files were committed to the remote repository branch configured for GitHub Pages.

#### **How to Verify:**

1. Open your browser and go to:
`[https://github.com/meitatsu2/_SurveyStatus](https://github.com/meitatsu2/_SurveyStatus)`
